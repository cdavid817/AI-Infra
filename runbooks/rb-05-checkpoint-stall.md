# Runbook 05:Checkpoint 卡住/拖慢训练

## 现象

- 同步保存场景:训练在 checkpoint 步长时间停顿,单步时长曲线上出现周期性尖刺,且尖刺高度(T_write)超过预算或持续变长;极端情况下保存卡死不返回,任务表现为 hang(与 [Runbook 01](rb-01-training-hang.md) 分支 B 的存储子分支互为入口)。
- 异步保存场景:训练步表面正常,但上传/落盘积压——本地暂存盘占用持续上涨、异步队列深度只增不减、最近一次"完成持久化"的 checkpoint 版本越来越旧。
- 存储侧告警:并行文件系统/对象存储写带宽打满、元数据服务(MDS)延迟飙升;同集群其他任务的数据读取变慢(checkpoint 突发写的挤出效应,机制见 [§14.4.3](../第三部分-数据底座/第14章-存储与Checkpoint-IO.md#1443-checkpoint-的突发写模式本章核心))。
- 开销越线:同步保存暴露时间 / 保存间隔超过该任务预先声明的训练开销预算，或保存窗口破坏共享读写 SLO。

## 影响范围

- **单任务级**:保存变慢直接计入本任务的训练停顿("存储抖一下、几千张卡集体罚站"的放大关系)。
- **集群级(常见!)**:checkpoint 是瞬时全集群突发写,共享存储被打满时,同存储上所有任务的数据读取与保存一起劣化——多个大任务的保存窗口撞车是典型的集群级事故。判定:存储侧聚合带宽/元数据延迟告警是否与多任务的停顿在时间上重合。
- **隐性风险面**:异步积压期间发生故障,可回滚的 checkpoint 比预期旧得多——影响范围要算上"潜在回滚损失被放大"。

## 立即止损

1. **判断保存是"慢"还是"无进展"**:对照同版本、同状态量的阶段预算；字节、完成分片或队列仍推进时先限流/等待，无任何阶段进展且超过任务告警窗口时按卡住处置。固定倍数不能跨存储路径复用。
2. **保存卡住时**:按框架支持的取消或任务终止流程中止本次 generation，禁止自行杀保存线程后继续修改可能共享的状态；确认该版本没有 commit marker，并从上一个已验证版本重启或按运行时能力继续。副作用是保护点后退，必须防止半成品被发布为 latest。
3. **临时拉大 checkpoint 间隔或暂停保存**(仅当存储侧确认短期内无法恢复):让训练先跑。副作用:回滚风险窗口拉大——间隔从 T 拉到 kT,单次故障平均回滚损失同步放大 k 倍;必须设定回收时限并记录决策人。
4. **集群级撞车时**:与其他大任务错峰——协调各任务的保存相位错开。副作用:需要跨任务协调,部分任务的间隔临时偏离最优值。
5. **异步积压时**:优先保证"最新一个 checkpoint 完整持久化",必要时丢弃积压队列中的中间版本(保留最旧未传完的之后的最新版本策略)。副作用:被丢弃版本不可回滚,checkpoint 序列出现空洞,需登记。

## 证据采集

- **本次保存的分解计时**:一致性/staging、队列、prepare、每 rank 数据与元数据、尾部同步、commit、verify；异步路径分别记录 staging 与 upload completion。
- **存储侧路径实测**:客户端、网络和后端吞吐，以及当前读写混合负载、队列深度、元数据延迟与 QPS。带宽只给数据段下界，不替代端到端计时。
- **文件布局事实**:本次保存产生的文件数(每 rank 一个还是每节点一个)、单文件大小、目标目录结构——元数据风暴的直接判据。
- **并发现场**:同时间窗内还有哪些任务在保存/在大量读数据(存储侧租户视图)。
- **异步链路状态**:暂存盘占用曲线、上传队列深度曲线、上传并发数与单流吞吐。
- **对照预算**:目标 state dict 的实测序列化字节、各 rank 分布、预算 pause/durable 时间与实测差距；`16N` 仅作为声明 BF16+Adam 状态组成后的早期估算。
- 采集口径参照 [§29.2.4](../第六部分-上层平台/第29章-可观测性与评测流水线.md#2924-训练侧可观测性与告警设计)。

## 诊断决策树

- **第一分叉:短板在哪一段?**(用保存分解计时判定)
- **分支 A:存储带宽打满**
  - 判定依据:写入按聚合带宽上限的平稳速率推进(慢但在动),存储侧带宽利用率贴顶;T_write 实测 ≈ S_ckpt / 实际可用带宽,公式对得上。
  - 细分:
    - A1 客户端侧短板:节点存储网卡跑满而存储侧远未饱和(常见于 8 卡共享 1–2 张存储网卡)。
    - A2 存储侧短板:聚合写带宽饱和,或读写混合下有效写带宽被数据集读取挤压。
    - A3 撞车:多任务保存窗口重叠,单看每个任务都在预算内,叠加后超限。
  - 下一步:A1 → 两级方案(先写本地 NVMe);A2 → 异步化摊平峰值或扩存储;A3 → 错峰调度。
- **分支 B:元数据风暴**
  - 判定依据:数据带宽远未饱和,但 prepare/create/close/commit 阶段占据关键路径；文件或对象并发上升时元数据延迟与尾部同步同步恶化。
  - 下一步:按目标后端测试聚合 writer、目录/前缀分桶或框架原生聚合格式；将元数据段作为实测分布进入预算，不添加跨环境固定秒数。
- **分支 C:异步上传积压**
  - 判定依据:训练步正常、本地暂存写得快,但暂存盘占用与上传队列深度单调上涨;上传吞吐 < 生成速率(生成速率 = S_ckpt / T_interval)。
  - 细分:上传带宽不足(单流吞吐低/并发数不够)vs 远端限流 vs 暂存盘写满反压训练。
  - 下一步:提高上传并发与分片、核对远端限流策略;不可持续时拉大间隔或压缩 S_ckpt(见修复)。
- **分支 D:保存路径卡死(非带宽问题)**
  - 判定依据:写入流量归零、保存调用不返回;常见于存储客户端挂死、挂载点失效、或保存逻辑内的集合同步等待某个卡住的 rank(此时真根因在别处,回 [Runbook 01](rb-01-training-hang.md) 分诊)。
  - 下一步:查挂载与存储客户端日志;确认是否单 rank 拖住全局保存;存储服务端故障则转存储值班。

## 修复

- **分支 A1/A2**:落地两级 checkpoint 方案——先写本地 NVMe(聚合带宽随节点数线性增长),后台异步上共享存储;或分片保存 + 异步化。方案对比与适用档位见 [§14.5.1](../第三部分-数据底座/第14章-存储与Checkpoint-IO.md#1451-三种-checkpoint-优化) 与 [§14.4.1](../第三部分-数据底座/第14章-存储与Checkpoint-IO.md#1441-三层存储的分工)。
- **分支 A3**:平台层为大任务的保存窗口做错峰编排,并把"保存带宽"当作可调度资源登记。
- **分支 B**:改保存布局为按节点合并文件;推动使用支持聚合写的 checkpoint 格式;目录按任务/时间分桶。
- **分支 C**:扩上传并发/带宽;必要时压缩 checkpoint 体量(只保留必要状态、分频次保存完整态与轻量态);为暂存盘设水位告警与反压策略(宁可拖慢保存也不能写爆盘)。
- **分支 D**:修复/重挂存储客户端;若是单 rank 拖住集体保存,按 Runbook 01 的根因处置。
- **通用**:修复后重测 $S_{ckpt}$ 、pause/durable 时间线、共享 SLO 与 restore；保存间隔若引用 Young 近似，必须记录同步周期保存、故障分布与恢复成本等假设，并受业务 RPO 约束。

## 恢复验证

- 实测 pause 与 durable 时间回到任务预算以内，且保存窗口没有破坏共享读写 SLO。
- 连续覆盖正常与高负载窗口的多次保存均产生完整 commit，无半截版本被 latest 引用；从最新版本做一次真实恢复并核对步数、状态与短程训练。
- 异步场景:上传队列有界并能在声明时间内消化；最新完整持久化版本与训练进度的落差满足 RPO。
- 存储侧:保存窗口内其他任务的读延迟无告警级劣化。

## 复盘数据

- **检测延迟**:保存耗时首次越线(从历史曲线回溯)→ 告警/发现。周期性尖刺变高常常被忽视数天,此值要如实回溯。
- **训练停顿总时长与损失卡时** = Σ(超预算的保存停顿 × 任务卡数) + 卡死处置的中断时长 × 卡数。
- **回滚保护退化量**:事件期间"可回滚点落后训练进度"的最大值(异步积压尤其要算);若期间真的发生了故障,实际多损失的回滚步数单列。
- 实测 vs 预算:S_ckpt、T_write、间隔三个数的对照表;短板归属(A1/A2/A3/B/C/D)。
- 作废/丢弃的 checkpoint 版本清单。

## 长期防复发

- **开训前预算门禁**:任务提交时携带 state dict 字节与分片分布、pause/durable 预算、保存间隔、RPO/RTO 和保留策略，平台校验容量、并发与故障域。
- **保存耗时与队列深度监控**:T_write、开销占比、异步积压深度、暂存盘水位全部纳入告警。
- **按证据启用两级方案**:共享保存窗口破坏训练或租户 SLO、且暂存故障域与容量满足 RPO 时，采用本地 staging + 有背压的持久化上传。
- **保存窗口错峰**纳入平台调度约束。
- **恢复演练制度化**:定期从生产 checkpoint 做真实恢复(防"写得出、读不回");与故障演练合并进 [§20.4.8](../第四部分-训练系统/第20章-稳定性与容错.md#2048-故障演练与-slo);恢复路径的成本结构见 [§20.4.6](../第四部分-训练系统/第20章-稳定性与容错.md#2046-断点续训与弹性训练恢复路径的成本结构)。

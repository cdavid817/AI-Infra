# Runbook 04:慢节点(straggler,不报错的降速)

## 现象

- 任务无任何报错,监控大盘全绿,但单步时长相比基线持续劣化(如 +10–20%),或 MFU/吞吐缓慢下滑——[§20.4.4](../第四部分-训练系统/第20章-稳定性与容错.md#2044-慢节点比故障更难的敌人) 定义的比故障更难的敌人。
- 横向对比特征:按 stage、TP/DP/EP 角色和输入形状分组，比较单步、计算、通信暴露与数据等待；嫌疑阈值取自健康窗口分布和业务最小可检测劣化，不使用通用 3–5%。
- 时间特征旁证:开跑漂亮、持续满载数十分钟后变慢(指向热节流,[§31.2.3](../第七部分-工程化与治理/第31章-容量、成本与SLO.md#3123-降频与热节流性能不稳定的头号真凶));或"换了机器就消失"。
- 全局同步语义:若慢 rank 持续位于不可隐藏的 step 关键路径，其劣化会传播到任务吞吐；传播比例由逐 rank 时间线实测，不能直接等同于该卡降速比例。

## 影响范围

- **单任务全量降速**:资源面只有一两个嫌疑节点,但成本面是整个任务的卡时在按劣化比例流失。损失速率 = 劣化比例 × 任务卡数 × 单卡卡时成本。
- **可能外溢**:热节流的根因若是机柜/机房级(热通道失效、密度超标),同机柜其他任务同样受害;网络劣化若在共享交换机,波及同交换机任务。确认根因分支后回头做波及面判定。

## 立即止损

1. **先量化再动手**:拉出全 rank 单步耗时分布,确认嫌疑对象与劣化幅度。副作用:多花几分钟;但没有横向对比数据就动手,大概率踢错节点。
2. **比较止损成本后再隔离**:若继续运行的累计损失已超过主动中断、回滚、重排与误判成本，则冻结现场后把嫌疑节点放入检修池并换入健康资源。若证据不足，先缩短观察窗口并限制产出发布。
3. **热备不足时的权衡**:用实测关键路径劣化、预计剩余运行时间和重排成本比较带病运行与缩容；缩容前验证新并行网格、全局 batch 与学习率语义。
4. **嫌疑指向机柜级散热时**,同步通知机房侧检查,并暂缓向该机柜调度高负载任务。副作用:局部容量下降。

## 证据采集

在踢除**之前**,对嫌疑节点抓齐四个分支的判定证据(节点一旦释放,现场难复现):

- **每卡温度、实时频率、功耗曲线**(与吞吐曲线同窗对齐)——热节流与降频判定的直接证据;同时记录节点在机柜中的物理位置(顶部/热通道末端是高危位)。
- **降频事件与原因寄存器**:设备报告的节流原因(热/功率/其他)、时钟历史。
- **单卡计算基准**:嫌疑卡 vs 健康卡各跑一次固定的单卡计算基准(如标准 GEMM),排除任务因素的纯硬件对比。
- **网络实测**:嫌疑节点与健康节点的点对点带宽/延迟、网口错误与重传计数、速率协商值。
- **运行时剖析**:抓一段时间线,区分嫌疑 rank 是"计算慢"还是"通信等待长"还是"等数据"(方法论见 [§5.4](../第一部分-基础与心智模型/第05章-CUDA、CANN与加速器软件栈.md#54-profiling-方法论全书唯一定义处),并行任务的逐 rank 对齐剖析见 [第 18 章](../第四部分-训练系统/第18章-并行运行时剖析.md))。
- **数据管道计量**:各 rank 的 dataloader 耗时与样本长度分布(数据倾斜分支的判据)。

## 诊断决策树

第一分叉:嫌疑 rank 的时间花在哪(计算、通信、等数据)。第二分叉:四个根因分支。

- **入口判定**:时间线剖析显示嫌疑 rank——
  - 计算 kernel 变慢 → 走分支 A/B;
  - 通信段变慢/带宽劣化 → 走分支 C;
  - 头部等数据变长、计算与通信均正常 → 走分支 D。
- **分支 A:热节流**
  - 判定依据:频率曲线与吞吐曲线同步下跌、温度曲线处于平台期高位;节流原因寄存器报"热";症状随持续满载时间出现、随降载消失;节点常在机柜高危位([§31.2.3](../第七部分-工程化与治理/第31章-容量、成本与SLO.md#3123-降频与热节流性能不稳定的头号真凶) 的判定三曲线法)。
  - 下一步:机房侧处置(清风道/滤网、调整机柜布局、封闭热通道、降密度);节点降温后复测单卡基准确认恢复。
- **分支 B:单卡硬件降级(非热)**
  - 判定依据:温度正常但单卡基准持续低于健康卡(HBM bank 降级、可纠正 ECC 反复修正拖慢访存、固件异常);或节流原因为"功率"而非"热"。
  - 下一步:转 [Runbook 03](rb-03-gpu-xid-ecc.md) 的隔离与检修流程;查 ECC/退役页计数佐证。
- **分支 C:网络劣化**
  - 判定依据:单卡计算基准正常,但该节点点对点实测带宽低于标称/低于健康节点;网口重传或错误计数上涨;速率协商到低档。
  - 下一步:按 [Runbook 02](rb-02-nccl-hccl-timeout.md) 的网络层/拓扑层分支处置(换线/换模块/修协商);排查方法见 [§7.4.8](../第一部分-基础与心智模型/第07章-互联与集合通信.md#748-网络故障的表现形式与排查)。
- **分支 D:数据倾斜/数据管道慢**
  - 判定依据:硬件与网络全部达标,嫌疑 rank 的 dataloader 耗时显著更长,或其分到的样本长度分布明显偏长(变长序列下计算量天然不均);"慢 rank"可能随 epoch/数据位点漂移而不固定在某台机器。
  - 下一步:这不是硬件问题,不踢节点。修数据侧:均衡分片、按长度分桶/packing、增加预取与预处理并行度(数据供给不等式见 [§13.4.1](../第三部分-数据底座/第13章-训练数据管道.md#1341-一条不等式统治全章));若为固有长尾样本,算法侧确认截断/分桶策略。

## 修复

- **分支 A**:机房散热处置完成、节点满载 1 小时稳态复测达标后归还资源池;机柜高危位登记,后续避免部署同等密度负载或纳入重点监控。
- **分支 B**:走 Runbook 03 检修/返修;修复后通过满载压力自检 + 单卡基准达标再归还。
- **分支 C**:走 Runbook 02 修链路;归还前点对点基准达标。
- **分支 D**:数据管道修复(分片均衡/分桶/预取),小规模验证各 rank 耗时方差回归后再上全量。
- 通用:任务已换节点重启的,修复动作与训练恢复并行进行,不阻塞训练。

## 恢复验证

- 全 rank 同角色耗时分布回到变更前健康区间，并覆盖足以复现原异常的稳态窗口。
- 任务吞吐/MFU、频率和温度回到预先登记的基线容差；容差与验证时长按负载波动和热稳态测量设定。
- 被处置节点归还后，单卡与点对点基准通过，观察期内未再次成为同类异常离群点；观察期由本地复发分布决定。

## 复盘数据

- **检测延迟**:降速实际开始(从历史吞吐曲线回溯拐点)→ 嫌疑确认。慢节点没有报错时刻,此值经常以天计——它是本故障类最重要的改进指标。
- **带病运行时长与损失卡时** = Σ(劣化比例 × 任务卡数 × 时长),从拐点算到恢复,含止损重启的中断成本。
- **定位时长**:嫌疑确认 → 根因分支确认;**误踢次数**:被踢后复测无异常的节点数。
- 根因分支(A/B/C/D)、涉事节点/机柜位置、劣化幅度峰值。
- 同构机器性能离散度(P95/P50 单步耗时比)作为集群健康度指标留档,汇入 [§20.4.2](../第四部分-训练系统/第20章-稳定性与容错.md#2042-有效训练时间占比稳定性的唯一北极星指标)。

## 长期防复发

- **横向对比告警常态化**:逐 rank 单步、计算、通信暴露和数据等待按并行角色建健康分布，阈值由误报/漏报演练校准([§20.4.4](../第四部分-训练系统/第20章-稳定性与容错.md#2044-慢节点比故障更难的敌人))。
- **温度/频率/功耗三曲线**纳入常规监控并与吞吐同屏([§31.2.3](../第七部分-工程化与治理/第31章-容量、成本与SLO.md#3123-降频与热节流性能不稳定的头号真凶) 判定法),对机柜高危位设更低的温度告警线。
- **验收与巡检测可持续算力**:到货验收与季度巡检跑满载 1 小时稳态基准,不收"前 10 分钟的峰值"。
- **入池门禁**含单卡基准与点对点带宽,拦住带病归还。
- **数据管道均衡性检查**进入训练模板:开训前对分片长度分布做一次静态校验。
- **演练**:注入单卡限频模拟慢节点,验证横向对比告警的检测延迟([§20.4.8](../第四部分-训练系统/第20章-稳定性与容错.md#2048-故障演练与-slo))。

# Lab 11:模型签名与 ML-BOM——验签失败即拒绝

| 项 | 值 |

## 目标

做完本 Lab 你能回答:第 30 章说的"供应链包 = 清单 + 各成员校验和,可整体签名、整体验证",以及"准入检查由机器执行、任一不过就拒绝",落到命令行上分别是哪几步。你将用 cosign 对一个模拟模型制品做 keyless 签名与验证,手写一份最小 CycloneDX ML-BOM 并通过 JSON Schema 校验,最后把两者串成一个"验签失败即拒绝"的准入脚本,并亲手演示篡改制品后准入被拒。

## 步骤

1. **构造模拟制品。** 建一个目录当作"模型包":一个几 MB 的随机内容文件模拟权重(`weights.bin`)、一个 `manifest.json` 记录包成员清单与每个成员的 SHA-256 校验和(对应第 30 章"清单 + 各成员校验和"的定义;可以再放一个小文件模拟 tokenizer,体会"换掉会改变行为的都进包")。对 `manifest.json` 本身取一次摘要——签名对象就是这份清单,清单锚住全部成员,即"对包整体签名"。
2. **keyless 签名。** 安装 cosign,用其对文件/blob 的签名子命令(`cosign sign-blob` 形态)对 `manifest.json` 做 keyless 签名:流程会跳转浏览器完成一次 OIDC 身份认证,换取短时证书完成签名,并把签名事件写入透明日志;保存输出的签名与证书。体会第 30 章的论断——没有需要长期保管的私钥。
3. **验证。** 用对应的验证子命令(`cosign verify-blob` 形态)验证:除签名与证书外,必须显式给出**期望的签名者身份与 OIDC 签发方**(即"签名者身份在不在允许清单里"),验证通过应同时确认透明日志中有该签名记录("签名记录在不在日志里")——正是第 30 章"验证退化为查两件事"的两件事。
4. **手写最小 ML-BOM。** 写一份 CycloneDX JSON:`bomFormat`/`specVersion` 等骨架字段,`components` 里放一个 `machine-learning-model` 类型的组件描述本模型(名称、版本、权重文件摘要),并按 CycloneDX 的 ML 扩展字段声明训练数据集来源与训练方法的最小信息(字段名以 CycloneDX 当期规范为准,本 Lab 只求"里面有什么"三要素成形:模型、数据来源、方法)。再放一个普通组件声明推理框架依赖,体会 BOM 同时覆盖模型与软件依赖。
5. **校验 BOM。** 从 CycloneDX 官方仓库取对应 specVersion 的 JSON Schema,用任意 JSON Schema 校验器(如 ajv、check-jsonschema,或 CycloneDX 官方 CLI)校验你手写的 BOM 通过;故意删掉一个必填字段重校验一次,确认校验器能抓到——保证你的"通过"不是校验器没生效。
6. **写准入脚本。** 几十行 shell/Python,模拟第 30 章图 30-3 的准入卡点,依次机器检查:(a) `manifest.json` 的签名验证通过且签名者身份匹配允许清单;(b) 包内每个成员的实际摘要与清单记录一致;(c) ML-BOM 通过 schema 校验且其中的权重摘要与清单一致。**任一不过,退出码非零并打印拒绝原因;全过才输出"允许进入可发布状态"。**
7. **篡改演练。** 三个负例逐一过准入脚本:(a) 改动 `weights.bin` 一个字节(成员摘要对不上);(b) 改动 `manifest.json`(签名验不过);(c) 用一个不在允许清单里的身份重签(签名有效但身份不匹配)。确认三者都被拒绝且拒绝原因指向正确的检查项。
8. **(可选)撤销演练。** 给准入脚本加一份本地"已撤销摘要列表",把当前包摘要加入后重跑准入,验证"标记撤销 → 拒绝新部署"这一动作——对应第 30 章紧急路径的第二级。

## 成功判据

- 未篡改的包:签名验证通过(含身份与透明日志两项确认)、BOM 通过 schema 校验、准入脚本放行;
- 三种篡改(改权重、改清单、换签名者身份)分别被准入脚本拒绝,且每次拒绝原因与实际篡改点对应——"验签失败即拒绝"由脚本退出码而非人工判断执行;
- 故意破坏的 BOM 被 schema 校验器捕获,证明校验真实生效;
- 你能对照第 30 章说出本 Lab 三类产物的分工:签名答"没被换过/谁出的",ML-BOM 答"里面有什么",而"怎么来的"(provenance)本 Lab 未覆盖、由 SLSA 类框架回答。

## 清理步骤

- 删除模拟制品目录、签名与证书文件、BOM 与准入脚本(或整体归档到实验目录);
- 无密钥需要销毁(keyless 的意义所在);注意透明日志中的签名记录是公开且不可删的——这正是步骤前安全提示的原因,模拟文件无此顾虑;
- 清除实验安装的工具(cosign、schema 校验器)或保留备用。

## 常见失败与排查

- **keyless 签名卡在认证**:无浏览器环境(远程服务器)用设备授权流程或换到本地机器做;企业网络拦截 OIDC/透明日志端点时需放行对应域名——这类端点依赖正是 keyless 方案的运行前提。
- **验证命令通过得"太容易"**:检查是否忘了指定期望身份与签发方——不校验身份的验签只证明"有人签过",允许清单那一半没有执行,等于白验;这正是准入检查最常见的形同虚设方式。
- **BOM 校验器不认 ML 字段**:确认 schema 版本与 BOM 声明的 `specVersion` 一致,ML 组件类型与扩展字段随规范版本演进,以 CycloneDX 当期规范为准,不要从旧示例整段照抄。
- **篡改权重后签名验证仍通过**:说明你签的对象没有锚住成员——签名只覆盖 `manifest.json`,成员完整性靠"清单里的校验和 + 准入脚本逐一比对"这一环兑现;漏了比对这一步,"对包整体签名"就退化成了"只签了一张没人核对的清单"。

## 目标

做完本 Lab 你能回答:第 28 章说"模型生成的代码在威胁模型上等同于不可信第三方代码",那么一个最小可用的执行边界要拦住什么、怎么拦、拦住之后留下什么证据。你将亲手配齐 §28.4.2 的**资源限制四维**(CPU、内存、磁盘、出网)加**墙钟超时**,验证每一维的越限行为都被机制(而非约定)终止,并给"高危操作"装一个绑定参数哈希的审批钩子,最后检查审计日志能完整回放整个过程。

## 步骤

1. **准备沙箱运行时。** 基线用普通容器(Docker/Podman,非 root 用户、只读根文件系统、drop 全部 capabilities);有条件的加装 gVisor(runsc)作为第二档运行时对照——对应 §28.4.2 三档中"容器"与"独立内核"两档。不使用特权模式,不挂载宿主敏感路径。
2. **写四个已知行为的测试片段。** 各十行以内的 Python/shell 片段,分别对应四维:(a) 纯计算死循环(打 CPU);(b) 循环追加大列表(吃内存);(c) 向工作目录写大文件(占磁盘);(d) 向一个外部地址发起 HTTP 请求(试出网)。再加 (e) 一个 sleep 很久的片段(测墙钟超时)。这些片段是演示"限制生效"的探针,不是攻击代码。
3. **配齐四维限制 + 超时并逐一验证。**
   - CPU:容器 CPU 配额限到 1 核以下,跑片段 (a),用宿主侧观察其占用被压在配额内、且不影响宿主其他进程;
   - 内存:设内存硬上限(如数百 MB),跑片段 (b),验证进程被 OOM kill 而不是拖垮宿主;
   - 磁盘:限制可写层/写入卷的容量(存储配额或独立小容量卷),跑片段 (c),验证写满即报错,宿主磁盘不受影响;
   - 出网:容器网络置为 none 或加默认拒绝出站的网络策略,跑片段 (d),验证连接失败;再配置一个白名单地址验证"默认拒绝 + 白名单放行"两态都工作;
   - 超时:执行器层面对每次运行设墙钟超时(§28.4.2 给的量级是 30–120 秒,演示可设更短),跑片段 (e),验证超时后进程被强制终止——注意验证是"进程真被杀了",不是"客户端不等了",对应第 28 章五机制表里"只停轮询不停任务"这一典型失效。
4. **加取消通道。** 写一个几十行的执行器脚本:提交片段后返回一个句柄,支持外部随时取消(向容器发终止信号并等待退出确认)。跑片段 (a) 后中途取消,验证资源立即释放。
5. **加审批钩子。** 在执行器里定义一类"高危操作"(如允许出网的执行请求):提交时计算请求参数的哈希并暂停等待人工审批;审批记录绑定该哈希,执行前重新校验——然后做一次演示:审批后篡改参数再执行,执行器应因哈希不一致而拒绝。这就是第 28 章"审批与请求内容绑定"防 TOCTOU 的最小实现。
6. **审计日志闭环。** 执行器把每次提交、限制配置、越限终止原因(OOM/超时/网络拒绝)、取消动作、审批记录(含哈希)写入结构化日志(JSONL 即可)。做完上述全部步骤后,只凭日志回放一遍:每个片段何时提交、被哪一维限制终止、谁批了什么。
7. **(可选,L1)GPU 不可见验证。** 在带 GPU 的机器上确认默认沙箱内看不到 GPU 设备——Agent 代码执行沙箱默认不应拿到加速器。

## 成功判据

- 四维越限片段全部被**机制**终止:CPU 被压在配额内、内存触发 OOM kill、磁盘写满报错、出网默认被拒且白名单放行有效;超时片段被强制杀死且资源释放;
- 取消动作使运行中的任务真正终止(容器/进程消失),而不是仅客户端停止等待;
- 篡改已审批请求的参数后,执行被哈希校验拒绝;
- 审计日志无断点:仅凭日志能重建每次执行的提交、判定、终止原因与审批链,对应第 28 章"事后审计回放"的要求;
- 你能说出容器档与 gVisor 档在本 Lab 中行为相同、差异在哪一层(隔离边界与逃逸风险面,见 §28.4.2 的三档表)——本 Lab 不验证也不尝试触碰该边界。

## 清理步骤

- 停止并删除全部实验容器与镜像,删除 gVisor 实验用运行时配置(若不再需要);
- 删除测试片段、执行器脚本产出的临时文件与大文件探针的残留;
- 审计日志按需归档或删除;
- 恢复实验中改动的容器运行时/网络策略默认配置。

## 常见失败与排查

- **内存片段没触发 OOM 反而拖慢宿主**:检查内存限制是否真的生效(cgroup v2 下确认 `memory.max`),以及是否开了 swap——沙箱内存限制配 swap 会把硬上限变软,演示前关掉或限制 swap。
- **出网"拒绝"了但其实是 DNS 失败**:网络 none 下连接失败可能报 DNS 错误而非拒绝,结论一样但证据要看清;验证白名单态时用 IP 直连排除 DNS 干扰。
- **超时杀不干净,子进程残留**:终止要发给整个进程组/容器而不是首进程;这正是第 28 章"取消"机制典型失效形态的现场版,修法是以容器为终止单元。
- **审批钩子被绕过**:确认哈希校验发生在执行器内部执行前的最后一步,而不是提交时——校验点错位就是 TOCTOU 窗口本身,参见「Agent Runtime 2.0」一节对审批绑定的论述。

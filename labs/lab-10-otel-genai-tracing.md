## 目标

做完本 Lab 你能回答:第 29 章那张"书内指标 → OTel GenAI 词汇"映射表落到代码里是什么样,以及一次 Agent 请求为什么在 trace 上呈现为一棵标准嵌套 span 树。你将给一个最小 Agent 循环(一次模型调用 → 一次工具执行 → 一次模型调用汇总)接上 OTel SDK,按约定打 `invoke_agent` / `execute_tool` 与模型调用 span,带上 token 用量属性,在本地 Jaeger 里看到与图 29-3 同构的层级,并验证**内容默认不采集、显式 Opt-In 才采集**的开关行为。

## 步骤

1. **起本地观测后端。** 用容器起一个 OpenTelemetry Collector + Jaeger(或直接用带 OTLP 接收端的 Jaeger all-in-one),只监听 127.0.0.1;应用侧 OTLP exporter 指向它。
2. **写最小 Agent 循环。** 几十行脚本即可:第 1 轮调用模型(托管 API、本地引擎、或一个返回固定 usage 字段的桩服务均可——本 Lab 验证的是遥测结构,不是模型质量),模型"决定"调用一个本地工具(如一次文件读取或算术函数),执行工具,第 2 轮把工具结果交回模型汇总。
3. **按约定打 span。** 用 OTel SDK 手工创建三层 span,层级与命名对照第 29 章映射表与图 29-3:
   - 最外层:`invoke_agent` 操作的 span,代表整次 Agent 请求;
   - 其内:两个模型调用 span(第 1 轮决策、第 2 轮汇总),各自记录 `gen_ai.usage.input_tokens`、`gen_ai.usage.output_tokens`(从响应的 usage 字段取真实值,桩服务则取桩返回值)与 `gen_ai.response.finish_reasons`;
   - 两次模型调用之间:`execute_tool` 操作的 span 包住工具执行;若工具内部还有子步骤(如沙箱/子进程),再嵌一层内部 span。
   属性名逐字采用约定词汇,不自造(第 28 章明确要求运行时打点直接采用这套词汇);属性全集与稳定性以约定仓库当期文档为准,本 Lab 只用映射表列出的锚点子集。
4. **看 trace。** 跑几次循环,在 Jaeger 里确认:一条 trace 下 `invoke_agent` 为根,两个模型调用 span 与夹在中间的 `execute_tool` span 为子节点,时间轴上能直接读出"模型在等工具还是工具在等模型"——即 §28.4.3 说的用分层 trace 取代日志考古。
5. **验证内容默认不采集。** 检查默认配置下所有 span 的属性与事件里**没有** prompt 与补全的原文(只有 token 数、结束原因、层级等结构信息)。然后实现一个显式 Opt-In 开关(环境变量或配置项):开启后才把提示词/补全作为事件记录(可加截断)。分别在关/开两态各跑一次,在 Jaeger 里对比同结构 trace 的内容差异,确认默认态干净、Opt-In 态才出现内容——这就是第 29 章"trace 记结构,内容走授权管道"的最小验证。
6. **(可选)collector 层属性映射。** 在 collector 配置里加一条属性改写规则(如把一个自造的临时属性名改写为约定名),体会第 29 章"在采集器层做映射、查询只面向映射后属性"的缓冲层做法。
7. **(可选)模拟一次工具超时。** 给工具执行加人为延迟触发超时,观察 `execute_tool` span 的时长与错误状态如何让"哪层在等"一目了然。

## 成功判据

- Jaeger 中一次 Agent 请求呈现为与图 29-3 同构的嵌套:`invoke_agent` → (模型调用 span,`execute_tool` span,模型调用 span),父子关系与时间轴正确;
- 模型调用 span 上有 `gen_ai.usage.input_tokens` / `gen_ai.usage.output_tokens` 属性,数值与响应 usage 字段一致(两轮的用量可分别读出);
- 默认配置下 trace 中检索不到任何 prompt/补全原文;打开 Opt-In 开关后内容以事件形式出现,关掉后恢复干净——开关行为可复现;
- 你能在 trace 时间轴上指出本次请求端到端耗时中模型调用与工具执行各占的份额(方向性读数,不要求精确基准)。

## 清理步骤

- 停止并删除 collector/Jaeger 容器及其数据卷(Opt-In 实验若采集过内容,确认该数据一并删除);
- 删除实验脚本的临时输出;若用了付费 API 的 key,从环境变量清除;
- 恢复/删除实验用 collector 配置。

## 常见失败与排查

- **Jaeger 里看不到 trace**:先确认 exporter 协议与端口(OTLP gRPC 与 HTTP 端口不同),再确认 span 被显式 end 且进程退出前 flush 了 provider——短脚本最常见的丢数原因是没 flush 就退出。
- **span 层级断裂,三个 span 各成一条 trace**:上下文没有传播——确认工具执行与第 2 轮模型调用是在父 span 的 context 内创建的(SDK 的当前上下文管理),异步/线程边界要手动传 context。
- **usage 属性取不到**:桩服务或某些引擎的流式响应里 usage 在最后一个块或需显式请求;拿不到就先用非流式响应打通,再处理流式,不要写死估算值。
- **默认态 trace 里出现了内容**:检查是否用了某个框架的自动埋点且其内容采集默认开——本 Lab 建议手工打点以看清默认边界;若用自动埋点,找到其内容采集开关并确认默认值,这本身就是第 29 章隐私边界一节要你养成的检查习惯。

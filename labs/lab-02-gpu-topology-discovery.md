## 目标

做完本 Lab,你能回答:

1. 你手里这台机器的完整描述是什么——几张卡、几个 NUMA 节点、卡间走 NVLink 还是 PCIe、网卡挂在哪个 PCIe 交换机下(而不是只会说"8 卡机");
2. `nvidia-smi topo -m` 输出矩阵里 `NV#`/`PIX`/`PXB`/`PHB`/`NODE`/`SYS` 各代表数据要走什么路,分别对应第 8 章三种亲和的哪一条;
3. 给定一个 4 卡任务,在这台机器上哪种卡组合是"好分配"、哪种是"坏分配",为什么([§8.4.3](../第二部分-算力底座/第08章-K8s上的加速卡.md#843-三种亲和及其冲突) 图 8-2 的本机版)。

## 步骤

**第一步:卡间拓扑矩阵。**

```bash
nvidia-smi topo -m
```

读懂矩阵的图例(命令输出自带 Legend):`NV#` 表示走 # 条 NVLink;`PIX` 同一 PCIe 交换机;`PXB` 跨多个 PCIe 桥;`PHB` 过 CPU 的 PCIe 根联合体;`NODE` 同 NUMA 节点内跨根联合体;`SYS` 跨 NUMA(走 CPU 间互联)。把矩阵抄下来,给每一对卡标注:属于 [§7.4.4](../第一部分-基础与心智模型/第07章-互联与集合通信.md#744-互联域与三级拓扑本章核心) 三级拓扑的哪一级、带宽量级差多少。矩阵最后几列的 `CPU Affinity`/`NUMA Affinity` 先记下,第三步用。

**第二步:PCIe 树。**

```bash
lspci -tv | less        # 找到 GPU 与 RDMA 网卡各自挂的桥
lspci | grep -i -e nvidia -e mellanox -e ethernet
```

在 PCIe 树上找到每张 GPU 和每张高速网卡的位置,判断"哪张网卡与哪几张 GPU 同交换机"——这是 [§8.4.3](../第二部分-算力底座/第08章-K8s上的加速卡.md#843-三种亲和及其冲突) 第三条(网卡亲和、GPUDirect RDMA 生效前提)的物理依据。若机器没有 RDMA 网卡,记录普通网卡位置即可,结论同样成立。

**第三步:NUMA 结构。**

```bash
numactl --hardware      # NUMA 节点数、每节点 CPU 与内存
cat /sys/bus/pci/devices/<GPU的PCI地址>/numa_node   # 每张卡归属的 NUMA 节点
```

与第一步的 `NUMA Affinity` 列互相印证。回答:如果 dataloader 进程被调度到与卡不同的 NUMA 节点,H2D 数据要多走哪一段([§8.4.3](../第二部分-算力底座/第08章-K8s上的加速卡.md#843-三种亲和及其冲突) 第一条)?

**第四步:画出你的机器。** 用任何工具(纸笔即可)画一张分层图:CPU/NUMA 节点 → PCIe 根联合体与交换机 → GPU 与网卡 → 卡间高速互联。对照 [§4.1.3](../第一部分-基础与心智模型/第04章-硬件第一性原理、架构范式与数值精度.md#413-规模层级互联域是关键抽象) 标出每条边的带宽量级(HBM TB/s、NVLink 数百 GB/s、PCIe 几十 GB/s、跨 NUMA 更低)。这张图就是"互联域"抽象在你机器上的实例。

**第五步:好/坏分配推演。** 假设要在这台机器上跑一个 4 卡任务(若只有 1~2 张卡,改为推演 2 卡任务或用第 8 章图 8-2 的 8 卡拓扑做纸面推演):

- 列出两种 4 卡组合:一种全部同互联域/同 NUMA,一种横跨;
- 用 [§7.4.2](../第一部分-基础与心智模型/第07章-互联与集合通信.md#742-集合通信原语四个动词与它们的通信量) 的 AllReduce 通信量 ≈ 2S 和两种组合的最低链路带宽,估算同一次梯度同步的耗时比——这就是 [§8.3](../第二部分-算力底座/第08章-K8s上的加速卡.md#83-问题场景调度成功性能腰斩) "调度成功、性能腰斩"的算术根源;
- 组合的有效带宽由**跨过的最低一级**决定([§7.4.4](../第一部分-基础与心智模型/第07章-互联与集合通信.md#744-互联域与三级拓扑本章核心) 短板效应),验证你的估算取的是短板值。

**昇腾侧对应**:Atlas 机器上用 `npu-smi info -t topo` 类命令查看 HCCS 组结构(典型 8 卡机是两个 4 卡全互联组,TP 切分必须对齐 4 卡组),工具与术语对照见 [§5.3](../第一部分-基础与心智模型/第05章-CUDA、CANN与加速器软件栈.md#53-cann-与昇腾软件栈两套完整并行的世界) 与 [附录 D](../附录/附录D-术语表.md#d1-cuda-与-cann-术语双向对照表);三级拓扑的分析方法完全同上,只是域边界的位置不同([§7.4.5](../第一部分-基础与心智模型/第07章-互联与集合通信.md#745-hccl-与昇腾互联))。

## 成功判据

- 交付一张本机拓扑图,包含:卡数、NUMA 节点数、每张卡的 NUMA 归属、卡间每一对的互联类型、网卡位置,且每条边标了带宽量级——三个来源(`nvidia-smi topo`、`lspci -tv`、`numactl --hardware`)的信息互相吻合,无矛盾;
- 能对"4 卡任务的好/坏两种分配"给出耗时比的量级估算,方向与 [§7.4.4](../第一部分-基础与心智模型/第07章-互联与集合通信.md#744-互联域与三级拓扑本章核心) "跨域跌 5~10 倍"一致(具体倍数取决于你机器的实际链路,不编造统一数字);
- 能用一句话按 [§7.4.4](../第一部分-基础与心智模型/第07章-互联与集合通信.md#744-互联域与三级拓扑本章核心) 的口径描述你的集群:"几个域、每域几卡、域间什么网络"。

## 清理步骤

全部为只读命令,无产物需清理;若在共享机器上操作,不要修改任何 NUMA 绑定或持久化设置。

## 常见失败与排查

1. **容器内 `nvidia-smi topo -m` 全是 SYS 或看不到部分卡**:容器只挂了部分设备,或 PCI 拓扑信息被运行时屏蔽——到宿主机(或申请 hostPID/只读挂载 `/sys` 的调试容器)重跑;这本身就是第 8 章"调度器只见数量、拓扑在节点侧"的一次体感。
2. **`numa_node` 读出来是 -1**:BIOS 未上报或单 NUMA 平台,用 `numactl --hardware` 确认节点数;单 NUMA 机器上第三步自然退化,不影响其余步骤。
3. **两张卡显示 PHB/SYS 但你以为有 NVLink**:确认卡型号是否支持、NVLink 桥接是否安装;消费级卡多数没有卡间高速互联,此时机内也只有 PCIe 一级,推演仍可做,只是域更小。
4. **想验证坏分配的实际性能损失**:需要跑通信基准,见 [Lab 03](lab-03-allreduce-effective-bandwidth.md)。

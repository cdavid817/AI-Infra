## 目标

做完本 Lab,你能回答:

1. 给定一个算子的形状参数($b$ 、 $s$ 、 $h$ 、 $h_{ff}$ 、 $a$ 、 $a_{kv}$ 、精度 $p$),如何**动手算出**它的算术强度(FLOPs/Byte),而不是背结论;
2. 为什么同一个 FFN 矩阵乘,prefill 时是 compute-bound、decode 时是 memory-bound——batch 从 8192 掉到 1,强度掉了几个数量级;
3. 在一张 Roofline 图上,batch(或 GQA 比例)拨到多少时,一个算子会从带宽墙的斜坡爬过拐点进入算力平台区。

这是 [§6.1](../第一部分-基础与心智模型/第06章-模型结构的定量分析.md#61-算子与瓶颈归属先知道钱花在哪) 四种典型情形的"亲手复算版":书里给了代入结果,这里要求你自己代一遍,并把参数做成可拨动的旋钮。

## 步骤

**第一步:准备环境。** 任何带 `matplotlib` 的 Python 3 环境即可(`pip install matplotlib`,无其他依赖;不锁版本)。

**第二步:把 §6.1 的四种情形写成函数。** 新建 `roofline_lab.py`,按下面骨架实现四个算子的 FLOPs 与访存字节数(公式全部来自 [§6.1](../第一部分-基础与心智模型/第06章-模型结构的定量分析.md#61-算子与瓶颈归属先知道钱花在哪),这里只是翻译成代码):

```python
# 形状参数:与 §6.1 算例一致的默认值
h, h_ff = 8192, 28672          # 隐层维度、FFN 中间维度
a, a_kv, d_head = 64, 8, 128   # 注意力头数、KV 头数(GQA 8:1)、头维度
p = 2                          # BF16,每元素 2 字节

def ffn_gemm(bs):
    """FFN 的一个 [bs,h]x[h,h_ff] 矩阵乘。prefill 取 bs=8192,decode 取 bs=1。"""
    flops = 2 * bs * h * h_ff
    bytes_ = p * (bs * h + h * h_ff + bs * h_ff)   # 读两个输入 + 写一个输出
    return flops, bytes_

def prefill_attention_naive(s):
    """朴素注意力(物化 s×s 得分矩阵):FLOPs = 4·s²·h,访存 ≈ 8·a·s² 字节。"""
    return 4 * s * s * h, 8 * a * s * s

def decode_attention(s, a_kv):
    """decode 每层每 token:FLOPs ≈ 4·s·h,读 KV ≈ 2·s·a_kv·d_head·p 字节。"""
    return 4 * s * h, 2 * s * a_kv * d_head * p

def intensity(flops, bytes_):
    return flops / bytes_
```

**第三步:复算四种情形。** 分别打印:

1. prefill FFN(`ffn_gemm(8192)`);
2. decode FFN(`ffn_gemm(1)`);
3. prefill 朴素注意力(`prefill_attention_naive(4096)`);
4. decode 注意力(`decode_attention(4096, a_kv=8)`,再算 `a_kv=64` 的 MHA 对照)。

每个情形输出三个数:FLOPs、访存字节、算术强度。与 [§6.1](../第一部分-基础与心智模型/第06章-模型结构的定量分析.md#61-算子与瓶颈归属先知道钱花在哪) 正文逐条对照。

**第四步:画 Roofline。** 横轴算术强度(对数)、纵轴可达 FLOPS(对数)。屋顶由两个硬件参数决定:峰值算力 $P$ 与 HBM 带宽 $B$,可达性能 $= \min(P,\ I \times B)$,拐点在 $I^* = P/B$ 。硬件参数从 [附录 A.1](../附录/附录A-加速卡与集群形态速查表.md#a1-主流加速卡参数对照) 任选一张卡代入(注意用该卡 BF16 稠密算力,不要用稀疏峰值)。把第三步的四个点标在图上,观察各自落在斜坡(memory-bound)还是平台(compute-bound)。

**第五步:拨动参数,观察切换。** 至少做三个扫描,每个扫描画一条"强度随参数变化"的轨迹线:

- **batch 扫描**:`ffn_gemm(bs)`,`bs` 从 1 扫到 16384——找出强度越过拐点 $I^*$ 的 `bs`,对照 §6.1 "decode 攒 batch 摊薄权重"的论断(强度近似随 $bs$ 线性增长,饱和于 $\min(bs, h)$);
- **GQA 扫描**:`decode_attention(4096, a_kv)`,`a_kv` 从 64 降到 1——验证强度正比于 $a/a_{kv}$ 提升,但始终够不到拐点(§6.1:GQA 缓解带宽压力,不改变定性);
- **序列长度扫描**:朴素注意力强度随 $s$ 是否变化?为什么 FlashAttention 能把它拉回 $O(s)$ 量级(只需推公式,不要求实现)。

**第六步(可选延伸):** 换一张带宽/算力比不同的卡(例如推理向的卡,见 [§4.2.2](../第一部分-基础与心智模型/第04章-硬件第一性原理、架构范式与数值精度.md#422-训练型与推理型负载的硬件诉求差异)),重画屋顶,观察同一批点的归属是否变化——体会"瓶颈归属是算子与硬件的联合属性"。

## 成功判据

- 四种情形的算术强度与 [§6.1](../第一部分-基础与心智模型/第06章-模型结构的定量分析.md#61-算子与瓶颈归属先知道钱花在哪) 给出的代入结果**同量级**:prefill FFN 在 10³ FLOPs/Byte 量级、decode FFN 在 10⁰ 量级、朴素 prefill 注意力约 $d_{head}/2$ 量级、decode 注意力(GQA 8:1)在 10⁰~10¹ 量级。不要求数字逐位一致(系数处理略有出入是正常的),差一个数量级以上则说明公式抄错;
- batch 扫描能明确指出一个越过拐点的 `bs` 值,且该值与"拐点 $I^* = P/B$ 、强度近似为 $\min(bs,h)$"的纸面推导一致(即 `bs` 约在数百量级,具体取决于所选卡);
- 能用自己的图向别人解释:为什么 decode 集群按 MFU 考核是错的(§6.1 结尾的归因陷阱)。

## 常见失败与排查

1. **算出的强度比书里高/低一个量级**:最常见是访存字节漏乘精度 $p$,或 FLOPs 忘了乘 2(乘加算 2 FLOPs)。逐项对照 [§6.1](../第一部分-基础与心智模型/第06章-模型结构的定量分析.md#61-算子与瓶颈归属先知道钱花在哪) 的公式重查。
2. **拐点位置怪异**:检查是否误用了稀疏算力或 FP8 峰值——Roofline 的 $P$ 必须与算子实际使用的精度一致,见 [§4.3](../第一部分-基础与心智模型/第04章-硬件第一性原理、架构范式与数值精度.md#43-数值格式与精度全书唯一定义处)。
3. **想拿真实 kernel 实测对齐纸面数**:本 Lab 的模型忽略片上缓存复用,实测有效访存可低 20%~50%(§6.1 的误差声明),定量对齐需要 profiling 方法([§5.4](../第一部分-基础与心智模型/第05章-CUDA、CANN与加速器软件栈.md#54-profiling-方法论全书唯一定义处)),不属于本 Lab 范围。

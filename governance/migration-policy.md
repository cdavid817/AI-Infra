# 非破坏式迁移原则

结构调整的第一目标是建立清晰入口和治理闭环,**不是移动文件**。现有章节 URL、外部引用和 Git 历史保持稳定。

## 原则

1. **新增优先于移动**:入口页、治理文档、Manifest 都以新增文件实现,不改动既有正文路径。
2. **登记先于迁移**:任何未来的文件移动,必须先在 [book-manifest.yaml](../book-manifest.yaml) 的 `legacy_paths` 段登记旧路径 → 新路径映射,并准备站点侧兼容(重定向或兼容页)。
3. **校验先于合并**:移动后必须通过内部链接检查、构建后 HTML 链接检查,并核对 README、外部引用中的固定链接。
4. **快照先于大版本**:执行批量迁移前保留至少一个稳定发布版本作为迁移前快照。
